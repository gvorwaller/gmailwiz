### Key Technical Insight

- **`include_granted_scopes=True` + oauthlib raises by default.** Google merges all previously-granted scopes for the account across OAuth clients (Giftlist's `gmail.readonly` and `contacts.readonly` got returned alongside gmailwiz's requested scopes). `oauthlib` rejects scope mismatch as an error. Set `OAUTHLIB_RELAX_TOKEN_SCOPE=1` BEFORE importing `google_auth_oauthlib` — order matters because the env var is checked at lib import time.

- **Anthropic API output cap is the silent killer of multi-sender prompts.** Initial `max_tokens=1024` for 48 senders truncated mid-JSON; parser failed; everyone went UNKNOWN. Fix: chunk to 25 senders/call, raise to `max_tokens=4096`, surface `stop_reason="max_tokens"` as an explicit warning. Default `max_tokens` is way too small for batch-classification prompts.

- **Codex caught what 5 Claude rounds didn't.** The masked-failure P1 (every per-message Gmail fetch failing → "no unread mail" success) was a side effect of a Round-3 Claude fix (per-message HttpError tolerance to survive sparse 404s). Adversarial review with shared training biases doesn't catch its own fix-induced regressions reliably; an independent reviewer with different priors does. Cross-review wasn't theater.

- **Python evaluates default arg values at function-definition time.** A monkeypatch of a module attribute won't affect function signatures that already bound the constant: `def f(p=DEFAULT): ...` pins `p`'s default to whatever `DEFAULT` was at import. Fix: use `Optional[X] = None` in the signature and resolve the default inside the body. `db.connect` had this right; `auth.get_credentials` didn't until Round 2 caught it.

- **`CREATE TABLE IF NOT EXISTS` doesn't add CHECK constraints to a pre-existing table.** Pre-existing rows / future writes against an old-schema table won't see the constraint. For a self-use single-machine project where the cache is replaceable, deleting the live db and letting it regenerate is the simplest correct fix. Real schema migration is Phase-2-and-later territory.

- **Interactive sub-prompts need both EOFError AND KeyboardInterrupt handlers.** Ctrl-D and Ctrl-C are different exception classes; spec said "Ctrl-C must be clean at every prompt" and the original `_prompt` only caught EOFError.
