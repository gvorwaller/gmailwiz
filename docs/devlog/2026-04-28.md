### Key Technical Insight
- **`gmail.modify` is in Google's *restricted* scope tier**, not just sensitive. Publishing to Production therefore requires a third-party CASA security audit (~$15K–$75K, multi-week). For a self-use CLI, the only realistic path is staying in Testing mode and accepting the 7-day refresh-token expiry. Internal-app mode would dodge the expiry but requires a Google Workspace domain (~$7/mo); not justified here. Giftlist made the same call for the same reason.
- **Re-using an existing GCP project for a new OAuth client is the right move.** A single project's consent screen serves multiple OAuth clients (web + desktop + etc.) — there's no benefit to a per-app project for self-use.
- **Doc was wrong by default.** The original `manual-items-todo.md` walked through creating a new project as if no prior project existed. Future-me would have done redundant setup. Updated devlog now reflects what actually happened, not the abstract plan.
