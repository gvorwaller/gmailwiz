### Key Technical Insight

**The big one: Cloudflare Tunnel "config source" determines what wins.** A tunnel can be `config_src=cloudflare` (managed by dashboard / API, ingress stored in Cloudflare) or `config_src=cloudflared` (managed by local `config.yml`). The two modes are mutually exclusive — the `--config` flag in the daemon args is ignored for ingress when the tunnel is server-managed. Symptoms when you don't know this: editing `/etc/cloudflared/config.yml` looks correct, `cloudflared --config X tunnel ingress validate` passes, the daemon restarts cleanly, but new hostnames silently don't route. The cloudflared log's "Updated to new configuration" line is the giveaway — it shows the JSON config the tunnel actually loaded, regardless of what's on disk.

Resolution: either PATCH the remote config via API (`PUT /accounts/{aid}/cfd_tunnel/{tid}/configurations`) or PATCH the tunnel itself to switch `config_src`. We took the first path since the existing `btc.gaylon.photos` and `m2.gaylon.photos` ingress rules also live in remote config — switching modes would have required mirroring them locally.

**Honorable mention: sqlite3 is thread-affine, but conftest monkeypatching of `DEFAULT_DB_PATH` is the load-bearing thing that keeps tests hermetic.** A future test that opens `gw_db.connect()` *before* the autouse fixture monkeypatches the module attr would silently write to the real `data/db/state.db`. The new `test_test_suite_does_not_touch_real_state_db` guard snapshots mtime around a one-pass run inside the test and asserts it doesn't move — belt-and-suspenders against future fixture refactors.
